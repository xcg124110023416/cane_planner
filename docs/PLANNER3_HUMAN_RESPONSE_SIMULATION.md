# Planner 3 转向反应延迟仿真

## 本阶段范围（2026-11-02）

用户要求先在实验中加入反应延迟，其他响应因素保留但默认不使用。
本阶段在 planner 3 的轻量 LFPC 执行层增加可选的转向反应模型，保留原理想
执行作为默认对照。延迟不是阻塞 sleep，也不是只延迟里程计显示：实际步态
先保持已响应的方向，在新方向提示到期后的步态边界采用它。

名义前进参数保持原值。转向增益、转速限制和步长扰动保留为后续设计，
本轮没有启用这些因素，也不引入相应的可调参数。
规划器从实际执行后的完整 LFPC 状态重新规划；不能把实际位置拉回参考轨迹。
方向提示使用绝对朝向，避免重复累加同一条相对转角。

现有行人时效、空间走廊和实际剩余步态碰撞保护继续有效。新模式的实际动作
若不同于名义动作，需要重新生成实际首步走廊并接受相同执行保护。保护介入
单独记录，不能当作无干预的人体跟随成功。该阶段只研究转向反应延迟，不
模拟停步反应、人体制动、定位误差，也不声称已验证真实视障使用者。

LFPC 只在步态边界更换转向，实际提示至生效还包含边界等待、规划与回调耗时。
当前默认有效步时为 0.28 s；不能把配置 0.3 s 当作精确在 0.3 s 时发生转向。
诊断需要同时记录配置延迟与实际生效时间。起点、目标和结束重置清除旧提示。

## 实际执行与显示

`SteeringResponse` 在每个可规划的步态边界接收一条绝对朝向提示，保存发出时间
和 `due=issued+delay`。从已到期提示中选最新的一条，未到期时保持此前响应的
绝对方向。只有成功推进真实 LFPC 后，才记录这条提示已经被实际采用。
没有每周期累加旧相对转角，也没有用 `sleep` 暂停 ROS。

仅修改实际首步的 `api`，`al/aw` 保持原值。MPPI 仍预测理想响应的名义轨迹，
没有把延迟模型纳入优化器；下一步则从实际完整 LFPC 状态规划。这一差异用于
评估现有算法对响应延迟的敏感性，不等于算法已经具备延迟补偿。

若动作不同于名义动作，复用执行校验器，为实际首步质心折线重新建立走廊，
校验落脚点、全部质心样本及与行人时间同步的相交情况。预检不推进 LFPC；
失败的实际动作不会因为名义计划安全就被放行。之后仍执行原有每 20 ms
剩余步态检查。源过期、地图变化或未来相交可以导致保护冻结。

`/mpc/best_traj` 和 `MPC_TimedPlan` 仍是名义预测，`MPC_TimedCollision` 是实际
延迟动作的已检查剩余步态，`/sim_odom` 和 `/mpc/path` 是实际执行状态。
`MPC_HumanResponse` 黄色箭头为最新提示，蓝色为实际朝向，文字为延迟及保护
介入次数。所有录制脚本已采集两个新话题，默认 RViz 配置已添加该图层。

## 参数与实验入口

- 默认关闭：不传参数就是原理想执行。
- 轻量启动：追加 `human_response_enable:=true human_reaction_delay:=0.3`。
- pedsim 启动器：追加 `--human-response --reaction-delay 0.3`；与行人的
  `--pedestrian-mode interactive|independent` 相互独立。
- 零延迟对照：启用模型并设为 `0.0`。延迟必须有限且非负；只支持 planner 3
  的轻量执行，不支持 Gazebo 或实机适配器。
- 新目标、起点和初始化清除队列与每目标保护计数；到达清除待执行提示。

建议保持地图、行人配置和规划参数一致，先对比理想、0.0、0.3、0.6 s。
记录到达、耗时、路径偏差、保护介入次数及实际延迟分布。保护为 STOP 连续
区间计一次，恢复 OK 后再次 STOP 才增加；包含启动等数据无效保护，可结合
`/mpc/stop_reason` 区分原因。不要把保护总次数直接当作碰撞次数。

## 响应诊断 v1

`/mpc/human_response_diagnostics` 的 `Float64MultiArray.layout` 自带索引说明：

| 索引 | 含义 |
| --- | --- |
| 0–3 | 版本、ROS 时间、启用标记、配置延迟 |
| 4–5 | 最新提示序号与绝对朝向 |
| 6–9 | 当前选中提示序号、发出时间、到期时间、绝对朝向 |
| 10–12 | 实际采用提示序号、首次推进时间、实际延迟；尚未采用时延迟为 -1 |
| 13–14 | 实际 LFPC 朝向、等待提示数 |
| 15–16 | 当前是否保护冻结、连续保护区间累计次数 |
| 17–18 | 已实际采用提示的发出时间与绝对朝向 |

提示序号在新目标时重置，跨目标统计须结合发出时间。时间使用 ROS 时钟，
pedsim 标准入口继续使用自有单调 `/clock`。

真实 pedsim `blank/crossing`、`independent` 模式：行人 `(0,-3)` 向 `(0,6)`
以期望速度 0.5 m/s 行走，模拟人起点 `(-5,0)` 朝 +X。测试包括：

| 模式与终点 | 观察窗口内到达 | 实际提示生效延迟 | 备注 |
| --- | --- | --- | --- |
| 理想执行，`(5,2)` | 是，9 s 观察结束时已到达 | 无响应队列 | 私有端口 48181 |
| 启用模型，0.0 s，`(5,2)` | 是，9 s 观察结束时已到达 | 0.002–0.021 s | 包含执行回调等待，26 条实际采用提示，端口 45099 |
| 启用模型，0.3 s，`(5,0)` | 是，9 s 观察结束时已到达 | 0.305–0.605 s | 17 条实际采用提示，端口 45401；该直行轮没有方向差 |
| 启用模型，0.3 s，`(5,2)` | **否，45 s 内未到达** | 0.303–0.607 s | 105 条实际采用提示，端口 46507；终点附近反复修正，最终 `(7.157,1.880)` |

转弯延迟轮的最新提示与实际朝向最大差约 0.659 rad，延迟前有真实位移；
保护计数为 1，日志对应启动等待行人数据，之后没有保护 STOP。
未到达是现有名义规划与延迟执行不匹配的负面实验结果，**不能说延迟模式下
导航已稳定或所有闭环测试通过**。本阶段不修改代价、步长或目标判定来掩盖它。
该轮执行检查 p95 约 0.397 ms，完整规划事务 p95 约 20.173 ms，仅代表本场景。

首个转弯轮另触发过 `conflicting duplicate batch`，桥接按原规则锁定为
`FAULT_RESTART_ROUND`；重跑得到上表的完整 45 s 结果。本次没有修改 pedsim
配对/时效保护，若后续复现应单独诊断，不能归为跟随成功或方向延迟效应。
