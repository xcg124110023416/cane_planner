SINGLE-ENTRY PEDSIM NAVIGATION
=============================
Optional dependency already built at /home/xcg/cane-pedsim-ws, fixed upstream
revision de3772630ae174b278da00bcf26e5cf6c2db5ab2 plus manifest-checked guard-v2.
No shell rc/system package changes. Do not remove old live workspaces while used.

After review/integration and user-authorized fresh round, ONE command:
  bash /home/xcg/ws/src/cane_planner/plan_manage/scripts/start_pedsim_navigation.sh
No manual source is required. Script loads primary and optional setup --extend,
checks patched upstream source hashes, rejects occupied private port11551,
exports the actual office PCD to a per-round temporary XML and runs one roslaunch
parent containing existing navigation+pedsim+bridge. It never attaches to11311.
An alternate unused private port uses start --port PORT. Do not launch two
rounds together: while masters differ, RViz windows/physical operator intent can
be confused. Script does not kill anything or auto-retry occupied ports.

In RViz set initial pose then a navigation goal. No goal means WAIT_GOAL; fresh
post-goal LFPC sim_odom plus actual upstream PAUSED_READY permit ONE automatic
unpause call. A* may initially STOP while waiting; existing STOP heartbeat
supplies true plant state. WAIT_PLANT/WAIT_INPUT means waiting for this evidence;
WAIT_PAIRED_OUTPUT means released and waiting for exact step pairing. RUNNING
means valid paired source, including stationary user after arrival. No hidden
pedestrian goal is sent to planner. Default deterministic launch remains unchanged.

FAULT_RESTART_ROUND: true stale/illegal/rollback/latch remains fail-closed and is
NEVER auto-unpaused again. Read /pedsim_single_bridge/status and upstream
/pedsim_simulator/guard_status on this round's master. Status publishes only on
transition. The .5s freshness and upstream guards are unchanged.

RESET: Ctrl+C in the single entry terminal, wait for its owned processes to exit,
then rerun the SAME command and set initial pose/goal. This restarts navigation,
simulator and bridge together. Do not manually unpause a fault or kill other ROS
nodes. Script intentionally leaves small per-round generated files for evidence.
